今天不跑任何训练，只看懂三件事：**SFT 干了什么** → **RL 干了什么** → **Doctor 和 Patient 怎么交互 + 怎么给奖励**。

---

## 一、SFT 主线

### 在干什么

让基础模型学会"当医生"的格式和套路。

SFT 数据里的每条样本长这样：
```
系统指令：你是一个医生，你要提问或诊断，格式是 <think>...</think> <answer>...</answer>
患者自述：腹泻、食欲不振、便血（男，37 岁）
标准回答：<think>患者有腹泻便血，需要了解持续时间...</think>
           <answer>Question：您好，这种情况持续多久了？</answer>
```

训练时模型看到系统指令和患者自述，试图生成标准回答，只对**回答部分**算 loss。

### SFT 数据怎么生成

这一步不能跳过，因为它决定模型具体在模仿什么。

从发布的数据可以还原出下面的过程：

1. 原始病例包含患者自述、真实多轮医患对话、诊断和建议。
2. 一个病例被拆成多条“当前对话历史 → Doctor 下一步动作”的样本。
3. 第一条样本只包含患者自述，目标回答是第一个问题。
4. 第二条样本在 prompt 中加入第一轮医患对话，目标回答是第二个问题。
5. 后续样本继续累积历史，最后一条的目标回答是诊断和建议。
6. DeepSeek 为每个 Doctor 目标回答补充 `<think>` 推理过程，再整理成最终 SFT Parquet。

以训练集第一个病例为例，它被拆成 5 条样本：前 4 条分别训练 Doctor 提出下一问题，第 5 条训练 Doctor 根据完整历史给出诊断和建议。因此 SFT 学到的是每个问诊阶段的“下一步动作”，不只是最后诊断。

仓库中的 `sft/generate_cold_start_sft.py` 只反映了第 6 步。它读取已有的 `prompt` 和 `response`，调用 DeepSeek 补充思考过程，并保留病例中的其他字段。

但当前仓库没有提供以下完整实现：

- 原始 MTMedDialog 怎样清洗成医疗病例。
- 一个完整病例怎样拆成多条逐轮 SFT 样本。
- DeepSeek 返回结果怎样被解析成当前发布 Parquet 的最终结构。
- 994 个训练病例和 100 个验证病例怎样切分。

现有生成脚本使用的输入文件也没有发布，输出字段处理与当前 Parquet 并不完全一致，所以不能只靠这个脚本从原始数据完整复现现在的 SFT train 和 val。

另外，当前发布的 549 条 SFT val 样本在 `prompt + response` 上全部出现在 train 中，因此它不是独立验证集。理解数据生成时必须把这个切分问题单独记录下来。

### 看完什么文件

| 文件 | 看什么 |
|---|---|
| `sft/generate_cold_start_sft.py` | 看已有 prompt 和 response 如何交给 DeepSeek 补充 think；同时确认它只是部分生成链路 |
| `self_scripts/extracted_samples/MTMedDialog_sft_train_first_10.json` | 顺着同一个病例观察 prompt 怎样逐轮增长、response 怎样变成下一步动作 |
| `sft/finetune_lora_med.sh` | 入口脚本。看基础模型、数据路径、LoRA 参数、保存位置 |

### SFT 主线一句话

```
数据(parquet) → 拼成对话模板 → 模型生成 → 只对医生回答算 loss → 更新 LoRA → 合并得到完整 SFT 模型
```

## 二、RL 主线

### SFT 和 RL 的数据有什么不同

**SFT 数据**给了完整的多轮问诊记录和标准回答，模型只是模仿。

**RL 数据没有标准回答**。每条样本只给患者自述（`enhanced_description`）和诊断标准（`ground_truth`），问诊过程由 Doctor 现场发挥，Patient 现场回答。

RL 数据的 prompt 里还嵌入了完整奖励规则：
```
+1 有效提问   -2 重复问题   -2 格式错误
-5 超轮未诊断   +10 诊断和建议完全正确
```

### GRPO 干了什么

同一个病例让 Doctor 尝试多种问法，每种得到一条完整问诊轨迹和总分。系统在病例内部比较这些分数：

- **高于均值**的轨迹 → 提高这些轨迹里 Doctor 行为的概率
- **低于均值**的轨迹 → 降低这些轨迹里 Doctor 行为的概率
- 用 **clip（0.2）** 限制单次更新幅度，防止一次学歪

### 看完什么文件

| 文件 | 看什么 |
|---|---|
| `ragen/trainer/ppo/ray_trainer.py` 主循环 | 一批病例 → 复制成多条轨迹 → 生成 → 算奖励 → 算优势 → 更新 |
| 同上 `compute_advantage` | GRPO 分支：进入组内优势计算 |
| `verl/verl/trainer/ppo/core_algos.py` `compute_grpo_outcome_advantage` | 同组奖励减均值 ÷ 标准差 |
| 同上 `compute_policy_loss` | 新旧概率比 + clip + advantage = loss |
| `ragen/workers/actor/dp_actor.py` `update_policy` | loss 反向传播，更新 Doctor |

### RL 主线一句话

```
RL 数据(parquet) → 同病例复制 N 份 → Doctor 生成 N 条轨迹 → 环境算奖励
→ 组内比优劣(advantage) → clip 限制后更新 Doctor 模型
```

## 三、交互 + 奖励主线

### Doctor 和 Patient 怎么交互

```
Doctor 生成动作 ──→ 环境判断动作类型
                        │
                    ┌───┴───┐
                    │       │
                是提问    是诊断
                    │       │
              Patient 回答   环境评价诊断
                    │          + 建议
              回到 Doctor    给出奖励
                    │
              继续下一轮
```

**一个动作**：Doctor 每次输出 `<think>推理</think> <answer>...</answer>`，answer 要么是 `Question: ...`（继续问），要么是 `Diagnosis: ... / Recommendation: ...`（结束）。

### 奖励怎么算

| 行为 | 奖励 |
|---|---|
| 有效提问（患者能答且对诊断有帮助） | **+1** |
| 重复问题 | **-2** |
| 格式错误（不是 think + answer 格式） | **-2** |
| 超过最大轮数还没给出诊断 | **-5** |
| 诊断和建议完全正确 | **+10** |
| 诊断部分正确 / 建议部分正确 | 各有部分加分 |

### 看完什么文件

| 文件 | 看什么 |
|---|---|
| `scripts_exp/doctor-agent-rl-rm-dynamic.sh` | 完整实验用了哪些组件：模型、数据、轨迹数、轮数 |
| `ragen/trainer/main_ppo.py` | 组装环境、Doctor、参考策略、Patient/Evaluator → 交给训练器 |
| `ragen/llm_agent/generation.py` | 多轮循环：Doctor 生成 → 环境受理 → Patient 回答 → 下一轮 |
| `ragen/env/medical_consultation/env_patient_llm_rm.py` | **奖励核心**：病例初始化、动作区分、Patient 回答规则、惩罚逻辑、总奖励 |
| `ragen/workers/env_llm_worker.py` | 批量跑 Patient 和 Evaluator（不用看 vLLM/Ray 细节） |

### 交互主线一句话

```
Doctor 提问 → Patient 按自述回答 → 环境累加奖励 → 直到 Doctor 给出诊断或超轮
→ 一条轨迹的奖励 = 单步奖励之和 + 最终诊断加分
```

## 四、RL 概念 ↔ 项目对应

| 概念 | 对应什么 |
|---|---|
| Policy | Doctor 模型 |
| Environment | 医疗问诊环境 |
| Observation | 患者最新回答 + 当前问诊状态 |
| Action | 提问 / 最终诊断+建议 |
| Trajectory | 一次完整问诊对话 |
| Reward | 格式+轮数+诊断+建议的综合分 |
| Group | 同病例的多条轨迹 |
| Advantage | 一条轨迹比同组均值好/差多少 |
| Reference Policy | 限制 Doctor 别偏离原模型太远 |
